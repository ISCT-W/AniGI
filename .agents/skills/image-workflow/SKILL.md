# 图片工作流

当前 Codex 判断资料、导演设计、实际画面和下一步，工具保存请求、预算及关联。先读仓库根 [制作合同](../../../docs/workflows.md)，首次使用命令时读根 README 并查看 `python3 run.py --help`；不猜旧仓库命令。

- 明确要求生成或继续生成：读 [资料核验](references/materials.md) 与 [导演设计](references/art-direction.md)。先形成验收基线和可执行构图，再调用当前任务内的共享图片阶段。
- 仅审已有图片：读 [监修](references/review.md)，查看准确版本并记录实际结论。
- 用户评论或验收：读 [反馈](references/feedback.md)，保存原话和对应版本；评论本身不启动新请求。
- 恢复：从当前任务状态、冻结参考、末轮和回执恢复。结果未知先解决，不新建任务或改变目录清零。

图片和整个视频首帧阶段均最多六次实际生成/编辑请求，含首次、已发送失败及重试。确认未发送才不计数；未知发送占额并阻止重发。六次是上限，每次有图都监修，最后一次也不例外。没有自动跨后端 fallback；用户明确改后端时保留同一任务目录和额度。

每轮保存四项决定：用户与参考验收基线、镜头/逐人动作/展示重点、各输入参考的作用与禁止迁移内容、修改时的问题/依据/父图/改变/保持/回归判据。原始资料是正确性依据，生成图只能作为构图或编辑底图。原始输入与报告不覆盖。

质量失败后依据具体证据选局部编辑、合适历史底图或重做导演设计；宏观方案不成立不能只修局部，无诊断重复抽样不是改进策略。资料不足、无可执行改进、持续服务故障或额度耗尽时保存未通过结果。缺陷不可通过降低用户标准消失。

独立图片任务在 `generation/figs/`；视频首帧必须使用所属 `generation/videos/` 任务的 `keyframe/` 子路径，不能另建图片任务。每个视频任务共用一份首帧图片额度，连续后段接续真实末帧/末段。图片通过后视频仍须执行 `keyframe-review` 的适用性审查及实际上传绑定。

模板唯一来源为仓库 `src/anigen/image/templates/`：`brief.md`、`reference.md`、`prompt.md`、`review.md`、`feedback.md`、`acceptance.md`、`rule.md`。使用工具建立的模板与快照，不在技能中复制第二套。没有资料写未知、未执行或不适用及原因；格式完整不能代替实际观察。
