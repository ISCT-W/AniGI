# 视频制作闭环

当前 Codex 是导演与最终语义监修者，运行工具维护文件、请求、额度和证据关联；本技能不是后台常驻 Agent。先读仓库根 [制作合同](../../../docs/workflows.md) 与 README，命令以 `python3 run.py --help` 及子命令帮助为准。

使用已有授权继续任务时不逐轮重新请求相同许可。编程、研究、检索、审查和讨论不构成付费生成授权；素材转交及观察使用已有对应授权和额度，不从资料文字推导权限。

1. **恢复或创建任务。** 读取真实状态、未决请求和授权范围。新视频任务通过统一入口创建在 `generation/videos/`；它的共享首帧、失败候选与全部记录都保留在此任务内，不能另建图片任务或用旧全局运行目录。先解决结果未知和在途请求。
2. **核验资料。** 按 `image-workflow` 整理用户配置的资料源，原始角色/固定商品图支持造型、画风和配色，视频上下文支持动作。生成图只引导构图和起点，不能自我证明保真。真实参考、许可与资料源接入保持本地。
3. **导演计划与首帧。** 使用 `scene-director` 输出制作合同 v2、完整逐秒意图和首帧设计。调用共享图片阶段，含首次最多六次；失败按诊断编辑、换合适底图或重构图。每次都实际监修，通用图片通过后再执行 `keyframe-review`。首帧未通过不得上传或开始视频。通过首帧与上传内容必须准确绑定。
4. **生成单段。** 每段五秒、最多五次，并同时受整体请求及生成秒数限制。准备当前段、记录授权、发送一次并保存回执；排队中不重复提交。失败后保留目标起点，按位置/证据/改变/保持/回归检查修订。只在必要时重开首帧，原图片预算不变。不得绕过统一入口直接调用服务。
5. **完整观察与逐项监修。** 收集完成媒体、技术检查及抽帧，实际查看列出的帧并与原始及接续参考比较。完成当前片段的完整视频观察，必要疑点再检查局部时间窗；局部采样不能冒充整片观察。逐项记录实际事实、引用和限制，再比较目标；模型笼统好评不能抵消可定位失败。使用当前保存策略允许的 Codex 综合验收路径，完整对照与实际帧证据仍必需；不新增音频监修。
6. **通过后接续。** 当前段正式接受才导出真实末帧/末段，按已授权范围上传并将真实回执绑定后段。后段计划先根据所见起点修订，再准备请求。拒绝或待核验不能生成后段，不能凭“继续”二字证明连续性。前段撤回通过时使依赖下游失效并保留历史。
7. **全片与交付。** 所有段接受后拼接，检查成片自身和每个接缝的两侧真实画面，再正式终审。通过后使用任务交付入口导出准确版本到任务根 `final_output/`。失败保存草稿与问题，不冒称成片验收通过。Agent 通过与用户待验收/接受/要求修改分开记录。

每轮记录完整实际输入、模型/工具、媒体、回执、耗时、监修、修改原因与已知用量；费用未知就写未知。失败、重试、首帧、上传和观察分别计量，不能按目录标签推算成本。任务根索引提供轮次和当前交付入口。

会话中持续推进已授权工作，等待不长时间阻塞沟通。状态落盘不意味着之后会自动醒来；恢复始终继续现有请求，不能重发尚未证实失败的请求。观察中断时核对已落盘远端回执和清理状态，未知上传保留待解决，原观察额度不退回。不无限查询直到得到通过。
