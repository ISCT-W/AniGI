# 制作与监修合同

AniGen 由当前 Codex 会话担任导演、资料核验者和监修者。程序维护请求、额度、内容校验值、状态和交付关系。字段齐全、文件校验通过或模型说“正确”，均不能证明实际画面满足要求。代码迁移和离线测试不授权真实生成，也不证明真实生成质量。

## 已核验参考

资料来自用户配置的资料源。公开核心接收通用参考记录：本地证据编号、用途、对象/版本、实际文件、内容校验值、已核验或未知状态、观察事实和限制。接入细节与真实内容保存在本地。搜索候选仅用于定位，实际看图、读原文或查看片段后才能记录其支持的事实。

先固定用户要求与验收基线，再划分严格保持项、允许变化和表达目标。角色、商品、服装版本、动作和环境分别绑定参考职责。原始参考是正确性依据；生成图只提供构图、编辑底图或已验证的运动起点。生成输入和审核依据分别保存，不能为了减少模型输入而丢弃审核依据。

关键证据缺失时停止相应制作并说明缺口。原创动作可以按任务允许范围设计，但不能冒充有原作依据的特定动作。只采用本次任务已授权使用及转交的资料；阅读授权不自动扩大为外部传输授权。

## 共用图片阶段

独立图片任务和整个视频首帧阶段各自最多六次实际图片生成/编辑请求，含首次。已发送失败和重试占额；明确未发送的本地失败不占额；结果未知时占额并阻止再次发送，先恢复已有回执或产物。重新打开任务、重做导演设计、换底图或恢复会话均不清零。

任务选用 GPT 或 Gemini 图片后端。没有自动后端切换；用户明确要求改用另一个后端时，在同一目录记录实际后端并继续累计额度。每次有图都做实际监修，包括最后一次。通过即停止，六次是上限而非必须使用的次数。

失败后保存问题位置与依据、原因假设、修改项、保持项及回归判据。局部缺陷可定向编辑；宏观构图或动作不成立时重新设计；适合的历史候选可以作为底图，但需明确缺陷，原始资料仍然有效。没有有效改进方案、资料缺失或额度耗尽时保存失败结果，不能选“最好的一张”伪装通过。

可见部分按实际景别审核。合理遮挡、背侧面及风格化透视本身不是错误；身份、核心互动或用户要求展示的细节不可读时仍应阻断。必要检查完成、没有阻断问题和影响验收的关键未知，才允许该准确版本通过。

## 视频首帧与逐段制作

视频采用制作合同 v2：先制作首帧，再逐段生成和审查。导演输出全片意图、每秒场景与镜头、各主体动作/注意力/情绪、因果和结束状态。每段五秒，后段计划在前段通过前只是条件性意图。当前流程不新增音频监修。

首帧除通用图片监修外，还要检查身份、画风、商品、接触、构图、动作可行性及所有严格保持项。首帧应与第一秒相接，手部占用、视线和移动空间必须支持后续动作。候选、图片报告、导演设计、参考版本、首帧报告和实际上传内容相互绑定；通用图片通过不能直接放行视频。

首帧生成采用 1–7 张 PNG/JPEG/WebP 原始参考。完整视频观察最多八个参考文件。视频证据先提取有来源的静图；超出数量、格式或尺寸能力时必须在付费前报告，不静默截断。图片、上传、视频和观察额度分开计量。

每个视频片段最多五次请求，并受任务整体次数及生成秒数预算约束。前段正式接受后才能从其真实末帧/末段制作接续材料，上传并绑定后段请求。拒绝或待核验状态不能进入下一段。视频失败通常修改当前五秒提示词并复用相同已审起点；首帧有错才重开首帧，使其下游失效，原图片额度不恢复。

每段必须完成媒体技术检查、实际抽帧观察和完整视频观察，再与全部适用原始参考及接续参考比较。抽帧只能支持所见时刻，不能单独证明时序正确。当前 Codex 综合验收路径需要完整对照观察、实际看过的帧、逐项事实与限制；已知失败不能被笼统的模型好评覆盖。资格要求和实际观察预算以保存的运行策略为准，不伪造人工认可。

所有片段通过后才拼接，并对成片自身完成终审；每个接缝查看真实两侧画面。改变已审媒体、参考或导演计划时，撤销依赖的通过状态并保留历史。有进行中或未知请求时先解决，不能靠新建运行逃避恢复。

## 保存、恢复和交付

一个任务只创建一个目录，按最终目的分类：

```text
generation/figs/{time}*{simple_task_description}*{generation_tool}/
generation/videos/{time}*{simple_task_description}*{generation_tool}/
```

时间为东京时区 `YYYYMMDDTHHMMSSffffff+0900`；简短描述最长 48 字符；图片工具标签是 `gpt` 或 `gemini`，视频为 `gpt-minimax` 或 `gemini-minimax`。分隔符为恰好两个字面 `*`。字段内不含路径分隔符或保留字符；重试和恢复保留原名，重名创建使用更晚时间，不能追加第四段。工具标签记录任务创建时选择，实际调用与费用以逐轮回执为准。

图片状态保存在任务 `image/`；视频首帧及失败候选保存在视频任务 `keyframe/`，视频状态在其 `video/<安全内部ID>/`。外层三段式任务名不能用作视频资源 ID。全部输入、资料、媒体、回执、监修、修改原因和反馈保留在任务内；任务根索引展示当前状态及每轮入口。已知用量和费用如实保存，服务未返回费用时写“未知”。

只有最终目的对应的准确通过版本可以复制到任务根 `final_output/`。视频首帧通过仅是中间结果。每次交付另存版本并绑定媒体与报告校验值；拒绝或撤回通过时保留历史，撤销当前有效交付指向。Agent 通过与用户验收分开记录，用户无回复仍为待验收。

所有真实任务、本地配置、原始资料及反馈均属于本地数据，不进入公开导出。发布过程见 [公开文件检查](publication.md)。
